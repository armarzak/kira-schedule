# Расписание Киры

**Приложение: https://armarzak.github.io/kira-schedule/**

Приложение на неделю для всей семьи: занятия Киры (школа и допы), смены взрослых,
личные дела (спортзал) и расчёт, кто отвозит и кто забирает. Плюс домашка по предметам.

Сейчас это **первый этап**: всё работает на одном устройстве, данные лежат в браузере.
Облако и МЭШ — следующие этапы, см. ниже.

## Запуск

```bash
python3 kira-schedule/dev-server.py
```

Обычный `python3 -m http.server` тоже работает, но он разрешает браузеру кэшировать
модули, и правки не видно без жёсткой перезагрузки.

Открыть http://localhost:4173. Сборки нет — обычные файлы, модули ES.

На телефоне: открыть ссылку в Safari/Chrome → «Поделиться» → «На экран «Домой»».
Дальше приложение открывается как обычное, работает без сети (service worker).

## Публикация

Приложение раздаётся с GitHub Pages из ветки `main`, корень репозитория:
https://armarzak.github.io/kira-schedule/. Обновление — обычный `git push`,
сайт пересобирается сам за минуту-две.

На телефоне: открыть ссылку, «Поделиться» → «На экран «Домой»». Дальше это
обычная иконка, приложение помнит данные и работает без сети.

## Как устроено

| Файл | Что внутри |
|---|---|
| `js/store.js` | все данные и запись в localStorage, пресеты смен |
| `js/logic.js` | занятия на дату, доступность людей, подбор «кто везёт/забирает» |
| `js/views/week.js` | главный экран недели |
| `js/views/shifts.js` | таблица смен и личные дела взрослых |
| `js/views/activities.js` | постоянные и разовые занятия |
| `js/views/homework.js` | домашка по предметам |
| `js/views/settings.js` | имена, приоритет, данные, заготовки облака и МЭШ |

### Как устроен день

1. **Школа** — из расчёта исключена: утром отводят оба родителя вместе, из школы
   Киру забирает Оля и ведёт к себе. В неделе школьный блок показывает только
   время, уроки и домашку — про логистику там не пишется ничего. Отключается галочкой
   «Школу отводим вместе, забирает Оля» в настройках — тогда школа станет
   обычным занятием с расчётом.
3. **Допзанятия** — возят только родители: у Оли на руках ещё Ксюха.
4. **Вечером от Оли домой** — идёт тот, кто раньше освободился. Если ни один не
   успевает до «Кира должна быть дома к» (по умолчанию 20:00), ставится
   «Оля приведёт сама». Если в этот день родитель и так забирает Киру на допзанятие,
   отдельной строки нет — вечер уже закрыт.

### Смены

Готовые смены свои у каждого: у Темы 8:30–17:30, 9:30–18:30 и 11:30–20:30,
у Юли 10:00–19:00. Список правится в «Ещё» → «Готовые смены», там же добавляются
новые. Кроме них в любой день можно поставить свободный день, «весь день занят»
или произвольное время.

### Правила подбора

1. Человек **свободен**, если нужное время вне его смены и вне его личных дел.
2. Личное дело с пометкой «можно сдвинуть» (спортзал) не блокирует полностью:
   человек попадёт в подсказку с припиской «сдвинуть спортзал», но только если
   полностью свободных нет.
3. «Время освобождения» для вечера — конец смены, сдвинутый личным делом,
   если оно попадает ровно на этот момент.
4. Если день человека не заполнен («?»), он в расчёт не берётся.
5. Ручной выбор перекрывает расчёт и сохраняется только для этого дня.

Время в пути сознательно не учитывается, и конец смены считается «впритык»:
смена до 17:30 и занятие в 17:30 считаются совместимыми. Если так не выходит,
в настройках есть «запас до и после смены» — он расширяет занятость на N минут
с обеих сторон.

## Общий доступ (Supabase)

Приложение раздаётся с GitHub Pages, а общие данные живут в Supabase: занятия,
смены, личные дела, назначения, домашка и общие настройки (имена, смены, правила).
Личное для устройства — кто за ним сидит и ключи подключения.

### Что сделать один раз

1. Создать проект на supabase.com.
2. В SQL Editor выполнить `supabase.sql` из этой папки — он создаёт таблицы,
   правила доступа, функцию входа по семейному коду и саму семью.
3. В Authentication → Sign In / Providers включить анонимный вход.
4. В Project Settings → API скопировать Project URL и ключ `anon public`.
5. В приложении «Ещё» → «Общий доступ» вставить адрес, ключ и семейный код,
   нажать «Подключить». То же самое повторить на остальных устройствах.

### Что нельзя класть в репозиторий

Адрес проекта и ключ `anon public` / `sb_publishable_…` публичные — их видно
в коде страницы, и это нормально. А **семейный код — это пароль**: он не лежит
ни в одном файле проекта, вводится руками на каждом устройстве и хранится
в менеджере паролей. В `supabase.sql` на его месте заглушка.

### Как это работает

- Вход анонимный: устройство получает пользователя без почты и пароля, а функция
  `join_family` по семейному коду записывает его в семью. Дальше правила доступа
  пускают только к строкам своей семьи.
- Ключ `anon public` публичный по задумке — он сам по себе не даёт доступа
  к данным, нужен ещё семейный код. Код длинный и случайный, он и есть пароль;
  чтобы его сменить, достаточно обновить `join_code` в таблице `families`
  и удалить лишние строки из `family_members`.
- Обмен построчный: каждое занятие, смена и задание — отдельная строка. Отправляется
  всё, что изменилось с прошлого раза, принимается всё, что изменилось у других.
  При одновременной правке одной и той же записи выигрывает более поздняя.
- Удаления переживают синхронизацию: на месте удалённой записи остаётся отметка,
  чтобы удаление доехало до других устройств, а не вернулось обратно.
- Обмен идёт при запуске, через полторы секунды после правки, при возврате в
  приложение и раз в 45 секунд. Без сети приложение работает как раньше, а при
  следующем подключении догоняет.

## Дневник МЭШ

Тянутся уроки и домашние задания (включая ЦДЗ) по предметам из списка —
по умолчанию русский, математика, окружающий мир, английский и литература.
Список правится в «Ещё» → «Дневник МЭШ», сравнение идёт по куску слова,
поэтому «Литературное чтение» и «Литература» попадают одинаково.

### Почему снимок, а не запрос из приложения

`*.mos.ru` не пускает зарубежные адреса: с VPN сайт дневника не открывается
вообще, и облачная функция-прокси (Supabase живёт в Ирландии) тоже получила бы
отказ. Значит, запрос должен уходить с устройства, которое и так ходит в дневник.

Поэтому данные снимает закладка `tools/mesh-snapshot.js`, запускаемая на самом
`school.mos.ru`: там запрос свой для страницы, CORS не мешает, а токен остаётся
в браузере и никуда не отправляется. Закладка кладёт в буфер компактный JSON,
а приложение его принимает кнопкой «Вставить из буфера».

Эндпоинты (host `https://school.mos.ru/api/`, заголовки
`Authorization: Bearer <aupd_token>` и `X-mes-subsystem: familyweb`):

| Что | Путь |
|---|---|
| профиль и id ученика | `family/web/v1/profile` |
| уроки на даты | `family/web/v1/schedule/short?student_id=&dates=` |
| домашка за период | `family/web/v1/homeworks?from=&to=&student_id=` |

Прямой запрос из приложения написан (`fetchDirect` в `js/mesh.js`) на случай,
если дневник всё-таки отдаёт CORS-заголовки, но это пока не проверено —
проверять нужно с российского адреса, без VPN.

### Как это ложится в данные

- Уроки становятся отдельными записями на дату и показываются под блоком «Школа».
- Домашка заводится с пометкой об источнике: при повторном снимке она
  обновляется, а задания, добавленные руками, не трогаются.
- Если задание пропало из дневника, оно убирается и у нас — но только в пределах
  периода снимка и только то, что пришло из дневника.
- Отметка «сделано» после первого раза остаётся вашей: снимок её не сбрасывает.
